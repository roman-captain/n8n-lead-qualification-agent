| F05 | Google OAuth sign-in window never opens from n8n | Clicking "Sign in with Google" in the credential dialog did nothing; no error shown in n8n itself | Browser silently blocked the popup rather than n8n failing | Address bar showed a blocked-popup indicator for `localhost:5678` | Allowed popups for `localhost:5678` in the browser | OAuth window opened correctly on the next attempt |
| F06 | `The OAuth callback state is invalid!` on the first successful-looking retry | Error shown immediately after allowing the popup and clicking sign-in again | The popup carried a stale state token generated during the earlier blocked attempt | Reproduced by retrying without reloading the page first | Reload the credential page before starting a new OAuth attempt | Sign-in completed and the credential showed "Account connected" |
| F07 | Agent confirms a save to the user when the underlying tool call actually failed | Before the tool sub-workflows were set to Published, all three tool calls failed with `Workflow is not active and cannot be executed`, yet the agent still replied "Your lead has been recorded" | The system prompt never specified what to tell the user when a tool call errors, so the model defaulted to an optimistic reply | Compared the execution trace (tool node output was an error) against the chat reply (claimed success) for the same run | Published the three tool sub-workflows — a manual Execute step inside a sub-workflow does not make it callable as a tool from the Agent. | F08 | Google Sheets credential needs reconnecting after about ten days of no use | `Could not load list. | F09 | A lead with no stated budget was saved instead of triggering a follow-up question | Agent replied "we have recorded your request" and the trace showed a real `save_lead` call (row L46, `qualification=cold`), contradicting `AC11` ("an incomplete lead is not written") | `qualification_rules.csv` rule R1 only covered a missing contact or an unidentified service; a missing budget was not covered by any `incomplete` condition | Compared the trace and the saved row against `AC11` and against `discovery.md`'s own edge-case table, which had already classified the L005 mock record ("no budget") as "missing information" from the start — the rule data just never implemented that intent | Extended R1's condition to "budget is not stated", updated in `data/qualification_rules.csv`, the live Google Sheet's `qualification_rules` tab, and the rule table in `discovery.md` | Re-ran the same message; trace stops at `read_rules → read_services`, no `save_lead` call, no new row, reply asks only for budget |
| F10 | Malformed tool input is silently written to the sheet instead of being rejected | `Tool - Save lead`'s trigger was given mock data with `budget_eur` as an object instead of a string, run directly against the sub-workflow.
